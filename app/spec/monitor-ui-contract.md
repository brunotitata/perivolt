# PeriVolt — contrato mínimo core/adaptadores → UI do monitor v1

17/11/2026 · TechLead · Qt Widgets conforme ADR provisório; contrato para implementar `app/ui`, não prova de build Qt ou suporte macOS. Painel Next é outro módulo.

**Ownership:** Frontend: widgets/apresentação e intenções do usuário em `app/ui`; Backend: composição do estado do core e comandos de aplicação; Hardware: descoberta/leitura/consentimento no adaptador; DevOps: CMake/toolchain. UI não abre HID/Bluetooth, executa diagnóstico, chama shell ou cria servidor.

**Piso de API/build (17/11):** Qt 6.2 Widgets; `PERIVOLT_BUILD_UI=OFF` por padrão, ON exige `find_package(Qt6 6.2 REQUIRED COMPONENTS Widgets)` e `Qt6::Widgets`. Usar somente APIs públicas disponíveis nesse piso, sem `Q_OBJECT` próprio nesta fatia; conexões para funções/lambdas com contexto QObject e entrega enfileirada à GUI. Core/parser C++20, presenter pode manter C++17 se seus headers permitirem; alvo que inclui core deve respeitar seu requisito C++20. Piso de API não é versão de distribuição recomendada nem certificação: DevOps fixa versão/patch mantido e toolchain compatível para futura CI; nenhum build Qt/macOS verificado. Referências: [Qt/CMake](https://doc.qt.io/qt-6/cmake-get-started.html), [Widgets](https://doc.qt.io/qt-6/qtwidgets-index.html).

**Interface lógica (DTO, sem dependência Qt no core):** produtor entrega snapshot completo imutável; UI substitui a lista no thread da GUI. Campos abaixo são contrato de fronteira, ainda não uma API implementada.

| Campo | Regra / origem real |
|---|---|
| `devices[]` | Vazio no início e sem descoberta real. Uma linha por `(device_id,component_id)`; nome é rótulo, não identidade. Nunca popular por fixtures ou pelo diagnóstico salvo automaticamente. |
| `state` | `perivolt::State` de `Battery::project(device,component,now_ms,epoch)` em `app/domain/battery.hpp`; preservar present, nível, três frescores, charging, connection, alert_eligible/suppression. Renderizar linhas presentes; remoção tira da lista ativa. |
| `percent: optional<double>` | Derivado **somente** de state.level.kind=reported_percent e valor finito 0..100; 0% válido. Nos demais casos vazio, nunca usar o default numérico de Level.percent. |
| `qualitative / diagnostic` | `Level.detail` quando kind=qualitative / invalid ou unavailable. Unknown/ausente exibe “Sem leitura”; qualitativo exibe rótulo sem converter em %. Stale mantém valor identificado como antigo. |
| `age_ms: optional<int64>` | Produtor calcula a partir da observação monotônica aceita, mesma época; State não contém timestamp. Sem base comparável: vazio, “Idade desconhecida”. Tick não renova medição. Tempo de importação nunca vira tempo da leitura. |
| `origin` | `session_observation` ou `historical_import`; origem/hora disponíveis e frescor visíveis. Sessão por si só não significa leitura contínua. Só mostrar “Monitorando” quando produtor confirmar ciclo ativo e observações atuais; fora disso “Leitura pontual”, “Desativado” ou “Sem leitura”. |
| `read_control` | Consentimento `off` (padrão), `requested`, `granted`, `denied`; separado de permissão do SO `unknown/granted/denied` e capacidade `unavailable/available`. `active` só pelo produtor. Consentimento/checkbox não inicia I/O por si só e nunca implica bateria conhecida. |

**Fluxo real:** adaptador autorizado fornece `Observation`; Backend registra identidade declarada, chama `observe` e `project` com relógio/época confiáveis, conserva metadados temporais para idade e publica snapshot. Core hoje é fonte única por chave; UI não faz merge. Entrega à GUI por sinal/slot enfileirado; relógio da UI só pede nova projeção. `evaluate/delivery` são responsabilidade Backend, não de renderização/timer; contrato atual de entrega é síncrono, sem callbacks antigos.

**Intenções da UI:** solicitar ativação/desativação e importar diagnóstico por escolha explícita. Backend/Hardware validam capacidade, consentimento e autorização antes de leitura; sem ligação implementada, controle desabilitado com explicação, sem chamada simulada. Importação mostra seção **“Diagnóstico histórico — leitura pontual”**, separada da lista ativa: 50% somente se consta no arquivo selecionado, nunca “live”, nunca `observe` para renovar idade/alertar. Estado de carga desconhecido mostra “Carregamento desconhecido”; cabo/100% não inferem carga.

**Aceites imediatos:** abrir com zero dispositivos e “Nenhum dispositivo detectado”; renderizar DTO recebido sem transporte; 0/100 reais preservados, ausência não vira 0%; histórico só após importar, com selo explícito e sem alerta; off/denied/unavailable não inicia leitura; atualização automática da UI só com snapshots reais do produtor. Sem produtor conectado, manter estado vazio/indisponível. Componentes básicos não dependem de Qt já compilado, captura nova, liberação de hardware ou integração do core congelado em QA.

**Fechamento MVP macOS (atribuição BIG BOSS, 17/11):** Backend possui `app/application/**` e define a API concreta injetável de ativar/desativar/projetar; Hardware possui produtor/transporte nativo em `app/adapters/attackshark-x11/platform/macos/**`; Frontend liga essa API em `app/ui/main.cpp`/MonitorWindow. Manter `ui::Snapshot` existente na fronteira. Discovery fornece candidatos, não bateria nem conexão atual comprovada: o produtor deve declarar identidade de sessão/endpoint, fonte, resultado e base monotônica por campo; Backend não inventa associação persistente, horário de medição ou conexão por simples existência de metadados. `Origin::metadata/synthetic/cache` do adaptador atual nunca vira percentual de sessão real. A futura saída nativa deve distinguir observação real de teste/cache e fornecer tempo/época comparáveis; `live=true` sozinho não basta. Relógio de recebimento só vale como observação se o produtor confirmar que recebeu medição nova. UI solicita consentimento, produtor confirma; ativação não equivale a permissão do SO nem libera I/O não autorizado. Cada solicitação tem geração/token: OFF cancela, impede novas leituras e invalida conclusões pendentes; nova ativação não aceita conclusão do token anterior. Falha/timeout mantém unknown ou valor anterior identificado como antigo, nunca renova sua idade; snapshot de controle informa motivo/capacidade indisponível. Leitura pontual não vira ciclo ativo. Sem alertas: composição não chama `evaluate/delivery`. Aceite de integração: fonte injetada explicitamente de teste comprova OFF→pedido→resultado→OFF e descarte tardio, sem aparecer como hardware real; aceite de suporte exige execução consentida no Mac/hardware alvo e QA. Interface nativa ainda indisponível não impede composição testável, mas impede afirmar leitura nativa funcional.
